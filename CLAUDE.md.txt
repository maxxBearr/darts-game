# Dartboard Prototype — Phase 2 Spec: Vertical Window Stage

## Overview

This spec adds a new **Stage 2 (Vertical Window)** between the existing Aim and Release stages in the throw mechanic. The full throw sequence becomes three stages:

1. **Aim** — drag the line horizontally, click to lock. *(Already implemented.)*
2. **Vertical Window (NEW)** — the locked line shrinks to a shorter segment based on a stat, then the player repositions it vertically with W/S or Up/Down, and presses Enter to lock it.
3. **Release** — the bounce marker moves within the shortened segment only (not the full line), player clicks to release. *(Already implemented, but needs to be scoped to the shortened segment.)*

No other systems change. The dartboard, scoring, dart markers, and HUD all stay the same — this is purely a modification to `throw_mechanic.gd` and the instruction text in `main.gd`.

---

## Coding Conventions

- **Static typing on ALL variables** — no untyped vars anywhere.
- **Frequent comments** — every function, every block of logic, every non-obvious line.
- **Exported variables with `##` doc comments** — describe what the variable does, what different values mean, and how it interacts with gameplay.
- **Export variables liberally** — anything tunable should be exported.

---

## Existing Code Reference

The throw mechanic currently lives in `throw_mechanic.gd`. Key things to know about the existing implementation:

- Uses a `ThrowState` enum: `IDLE, AIMING, RELEASING, DONE`
- The aim line spans the full vertical height of the board (from `_board_center.y - _board_radius` to `_board_center.y + _board_radius`)
- After aim is locked, the release marker bounces using a sine wave across `_board_radius * 0.85` vertical range
- Variance is applied during `_resolve_throw()` using `randf_range` for both horizontal (aim_accuracy) and vertical (release_accuracy) offsets
- The `_draw()` function handles rendering for both AIMING and RELEASING states
- Input is handled through `_unhandled_input` using left mouse clicks to advance between states
- Signals: `throw_completed(hit_position)` and `state_changed(new_state)`

## Changes Required

### 1. Add New ThrowState

Add `POSITIONING` to the `ThrowState` enum between `AIMING` and `RELEASING`:

```
enum ThrowState { IDLE, AIMING, POSITIONING, RELEASING, DONE }
```

---

### 2. New Exported Variable

Add the following exported variable to `throw_mechanic.gd`:

```gdscript
## Controls how much the vertical window shrinks after aiming.
## Higher value = more shrinkage = tighter window = more accurate.
## Represents the fraction of the full line that gets removed.
## 0.0 = no shrinkage (window stays full height, stat is useless).
## 0.8 = shrinks to 20% of original height (very tight, very accurate).
## Typical gameplay range: 0.3 to 0.7.
@export var vertical_accuracy: float = 0.5
```

Also add visual exports for the window:

```gdscript
## Color of the vertical window segment during positioning.
@export var window_color: Color = Color(0.2, 0.8, 0.4, 0.3)

## Color of the vertical window border/outline.
@export var window_border_color: Color = Color(0.2, 0.8, 0.4, 0.7)

## Speed at which the player can move the window up/down (pixels per second).
@export var window_move_speed: float = 300.0

## Duration of the shrink tween in seconds.
@export var shrink_tween_duration: float = 0.4
```

---

### 3. New Internal State Variables

Add these to track the vertical window:

```gdscript
# Vertical window state
var _window_top: float = 0.0       # Current top edge of the shortened window (global Y)
var _window_bottom: float = 0.0    # Current bottom edge of the shortened window (global Y)
var _window_height: float = 0.0    # Current height of the window in pixels
var _window_center_y: float = 0.0  # Center Y of the window (used for repositioning)
var _is_shrink_complete: bool = false  # Whether the tween has finished
```

---

### 4. Stage Flow — AIMING → POSITIONING Transition

When the player clicks to lock the aim line (currently transitions from AIMING to RELEASING), it should now transition from AIMING to POSITIONING instead.

On entering POSITIONING:

1. Record the full line bounds:
   - `_full_line_top = _board_center.y - _board_radius`
   - `_full_line_bottom = _board_center.y + _board_radius`
   - `_full_line_height = _full_line_bottom - _full_line_top`

2. Calculate the target window height:
   - `_window_height = _full_line_height * (1.0 - vertical_accuracy)`
   - Clamp to a reasonable minimum (e.g., 20 pixels) so it never becomes invisible.

3. Start a tween that visibly shrinks the line from full height to the target window height:
   - The shrink should be **centered** — both ends move inward evenly toward the center of the line.
   - Tween duration is controlled by `shrink_tween_duration`.
   - During the tween, the player cannot move the window or proceed. Set `_is_shrink_complete = false`.
   - When the tween completes, set `_is_shrink_complete = true`.

4. After the tween, the window center starts at `_board_center.y` (vertically centered on the board).

---

### 5. Stage Flow — POSITIONING Input

While in POSITIONING state and `_is_shrink_complete == true`:

- **W / Up Arrow:** Move the window upward (decrease `_window_center_y`) at `window_move_speed * delta` pixels per second.
- **S / Down Arrow:** Move the window downward (increase `_window_center_y`) at `window_move_speed * delta` pixels per second.
- **Clamp** the window so it stays within the original full line bounds:
  - `_window_center_y` should be clamped so that `_window_top` never goes above `_full_line_top` and `_window_bottom` never goes below `_full_line_bottom`.
- **Enter key:** Lock the window position and transition to RELEASING state.

Update `_window_top` and `_window_bottom` every frame based on `_window_center_y`:
```
_window_top = _window_center_y - _window_height / 2.0
_window_bottom = _window_center_y + _window_height / 2.0
```

---

### 6. Stage Flow — POSITIONING → RELEASING Transition

When Enter is pressed to lock the window:

1. Transition to RELEASING state.
2. The bounce marker now moves **only within the window bounds** (`_window_top` to `_window_bottom`), not the full line height.
3. The sine wave bounce range should use `_window_height / 2.0` instead of `_board_radius * 0.85`.
4. The bounce center should be `_window_center_y` instead of `_board_center.y`.

So the release marker Y position becomes:
```gdscript
_release_y = _window_center_y + sin(_bounce_t) * (_window_height / 2.0)
```

---

### 7. Drawing — POSITIONING State

Add a new draw case for `ThrowState.POSITIONING`:

1. Draw the **locked aim line band** (same dimmed version as in the current RELEASING draw code — the vertical stripe at `_locked_aim_x` with `aim_accuracy` half-width).
2. Draw the **vertical window** as a highlighted rectangle within the aim band:
   - Position: from `_window_top` to `_window_bottom`, horizontally spanning the aim band width.
   - Fill with `window_color` (semi-transparent).
   - Draw a border/outline with `window_border_color` for clarity.
3. The area of the aim band **outside** the window should remain the dimmed aim line color, so the window visually "pops" as the active zone.

During the shrink tween, the window should animate smoothly from full line height down to the target height. The easiest way to handle this is to tween `_window_top` and `_window_bottom` from their full-line values to their target values, and just draw based on current values every frame.

---

### 8. Drawing — RELEASING State (Updated)

The existing RELEASING draw code needs to be updated:

- The locked aim band still draws at full height (dimmed).
- The vertical window rectangle draws within it (same as POSITIONING, but now locked in place).
- The bounce marker and glow zone are constrained within the window bounds.
- The glow zone rectangle should be clipped to the window if it would extend beyond the window edges.

---

### 9. Signal Updates

Emit `state_changed` when transitioning to POSITIONING:
```gdscript
state_changed.emit(ThrowState.POSITIONING)
```

Also emit it when transitioning from POSITIONING to RELEASING:
```gdscript
state_changed.emit(ThrowState.RELEASING)
```

---

### 10. main.gd Updates

Update `_on_throw_state_changed` to handle the new state and show appropriate instructions:

```gdscript
func _on_throw_state_changed(new_state: int) -> void:
	match new_state:
		ThrowMechanic.ThrowState.POSITIONING:
			hud.show_instruction("Use W/S or Up/Down to position the window, Enter to lock")
		ThrowMechanic.ThrowState.RELEASING:
			hud.show_instruction("Click to release the dart")
```

Note: The `state_changed` signal already exists and passes the new state. The `_on_throw_state_changed` function in `main.gd` currently just shows a single instruction regardless of state — it needs to match on the state value to show different text for POSITIONING vs RELEASING.

## Summary of the Full Throw Sequence (After This Spec)

1. **AIMING:** Player sees the dartboard with a vertical highlight band following their mouse horizontally. Band width = `aim_accuracy * 2`. Player clicks to lock horizontal position.

2. **POSITIONING:** The locked band visibly shrinks (tween) from full board height to a shorter window. Shrink amount based on `vertical_accuracy`. Player uses W/S or Up/Down to slide the window vertically to their desired target zone. Player presses Enter to lock the window.

3. **RELEASING:** A marker bounces up and down within the locked window only. Bounce speed based on `release_speed`. Player clicks to release. Dart lands at the marker position plus variance from `release_accuracy` (vertical) and `aim_accuracy` (horizontal).

4. **DONE:** Dart appears on board, score displays, player can throw again.

---

## What "Done" Looks Like

1. After clicking to lock aim, the line visibly shrinks with a smooth tween animation.
2. After the tween, the player can move the shortened window up/down with keyboard.
3. The window is clamped to board bounds and visually distinct from the dimmed aim band.
4. Pressing Enter locks the window and starts the bounce marker within it.
5. The bounce marker stays within the window bounds (never bounces outside it).
6. All new values (vertical_accuracy, window_move_speed, shrink_tween_duration, colors) are exported with descriptions.
7. Existing functionality (scoring, dart placement, HUD totals, clear board) is unchanged.
